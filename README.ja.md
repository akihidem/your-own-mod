# Your Own Mod

「結論から教えて」を、今日もまた。  
自分の取扱説明書を渡して、AI のふるまいを自分向けに。  
**17本のレシピ**から説明書に合うものを提案。入れるかは自分で選べます。

[English](README.md)

Your Own Mod（コマンド名は `kokoro-mods`）は、`kokoro.md`、`torisetsu.md`、`HUMAN.md` などのAI向け取扱説明書を読みます。そこに書かれた希望から、Claude Code に添える小さな追加機能、function-hook プラグインを提案します。提案には、きっかけになった本人の行をそのまま引用します。何を入れるかは、本人が選びます。

一部の動作の回数を数えますが、本人や AI が書いた文は記録しません。何が動いたか、前と回数がどう違うかを後から確かめられます。いつものお願いを、Claude Code の画面に貼る付せんにするような道具です。

普段から Claude Code を使い、「結論から答えて」「誤字を指摘しないで」「push の前に聞いて」「まだ動いているか教えて」と、同じお願いを繰り返す人向けです。

心理士と一緒にまとめた `kokoro.md` も同じしくみで使えますが、その手助けは必須ではありません。自分で短い説明書を書くこともできます。具体的な場面、してほしい応答、本人の許可が必要な操作を書いてください。書き方を案内する準備中のキットは、公開したらここから案内します。

`kokoro.md` は **KOKORO specification（KOKORO仕様）** に沿った、本人のためのAI向け取扱説明書です。Your Own Mod は、この仕様の著者でもある公認心理師（日本の国家資格）が設計しました。KOKORO との関係は[後述](#kokoro-との関係)します。

特性やクセ、得意・苦手、困りごとと、作業でどう対応してほしいかを書きます。診断名や検査の点数は書きません。内容チェックはそうしたラベルや、ほかの禁止内容を拒否します。このツールは診断や治療の代わりではありません。

[紹介に使える短い文](docs/share-copy.md)も用意しています。

## 大切にしていること

1. すべての提案に、本人が書いた言葉をそのまま1〜3行引用します。診断名は使わず、書かれた希望を手がかりにします。
2. 読み取り・照合・生成はオフラインで行います。モデルを呼ばず、ネットワークにも出ません。同じ入力とオプションなら、ツールが管理するファイルの内容はバイト単位で同じです。
3. 作るのは提案のフォルダーです。本人が読んで、選んで、インストールします。CLI が Claude Code の設定を変えることはありません。
4. 初めから有効になるレシピは最大3つです。`--max-enabled` と `--all` で変えられます。ほかの一致したレシピも、後からオンにできる状態で残ります。通知は共通で60秒の間隔を空けます。
5. 数えるのは動作の回数です。プロンプト（AIへの入力）、回答、ツール出力、説明書の本文は記録しません。
6. 説明書の引用は `plugin/` の外にある非公開用レポートに置きます。配布用フォルダーに入るのは、カタログの文面、範囲を制限した設定値、本人が選んだプラグイン名（省略時は `profile`）、説明書の SHA-256（版を表す指紋のような値）です。

## インストールと実行

Node.js 22以上が必要です。CLI（ターミナルで使うコマンド）に依存パッケージはありません。生成したプラグインには、Claude Code の早期アクセス版 function-hook API が必要です。これは、作業中の決まった場面で処理を動かすしくみです。

```sh
npx kokoro-mods --help
```

`npx kokoro-mods` は npm に公開された後に使えます。それまでの間、またはソースから使う場合は、このリポジトリを clone して手元に取り込み、ルートディレクトリに移動します。`node bin/kokoro-mods.mjs --help` を実行し、ほかのコマンドも同じ接頭部分で使ってください。

パッケージのインストールにはダウンロードが伴うことがあります。CLI の check・propose・diff・report・recipes はネットワークを使いません。ヘルプの終了コードは0です。

まず、説明書をチェックして提案を作ります。

```sh
kokoro-mods check   profile.md
kokoro-mods propose profile.md --out ./mods/me --name me
```

`./mods/me/PROPOSALS.md` を読んでください。その後、`propose` が表示したインストールコマンドを **Claude Code の中で**実行します。プラグイン名が `kokoro-mods-me` の場合は次の2つです。

```text
/plugin marketplace add ./mods/me/plugin
/plugin install kokoro-mods-me
```

`PROPOSALS.md` の相対パスは、出力フォルダーから見た場所です。CLI は、今いるディレクトリから使えるパスを表示します。

フォルダー名でプラグイン名は決まりません。名前を選ぶには、初回と再生成の両方で `--name me` を付けます。省略すると `kokoro-mods-profile` になり、CLI が案内を出します。名前は説明書から作らないため、タイトルや frontmatter（文書の先頭にある設定欄）の名前が配布物に入ることはありません。英数字を含まない `--name` や、診断名を含む `--name` は終了コード2で拒否します。`--out` を省くと、保存先は `./kokoro-mods-out/<slug>` です。各レシピのオン・オフは Claude Code の `/config` で切り替えます。

説明書を直したら、同じ提案コマンドをもう一度実行します。差分を表示してから、ツールが管理するファイルを入れ替えます。承認待ちやインストールは行いません。自分で追加した別のファイルは残ります。プラグイン名が変わると終了コード5になり、`--force` を付けたときだけ入れ替えられます。

準備用の一時フォルダーは、出力フォルダーと同じ親の下に作ります。ツールが管理するファイルの一覧は `PROPOSALS.json` の `files` 配列に記録します。`PROPOSALS.json` がカタログと合わない場合は、中身を読む前に拒否します。手で編集したものでも、別のツールが書いたものでも同じです。

```sh
kokoro-mods propose profile.md --out ./mods/me --name me
kokoro-mods diff old/PROPOSALS.json new/PROPOSALS.json
kokoro-mods report export.json export-before.json --settings ~/.claude/settings.json
kokoro-mods recipes
```

1つの集計だけを見るなら `export-before.json` を省きます。設定を読まず回数だけを見るなら `--settings` を省きます。差は「1つ目の集計 − 2つ目の集計」です。リセット後は負になることもあります。2つの集計は同じプラグインのものでなければなりません。説明書のハッシュが違う場合は警告を出します。

設定ファイルは読むだけです。レポートは、その集計のプラグインについて、設定で明示的にオンにした項目を示します。設定に項目がないだけでは、既定値は分かりません。

## Claude Code の中のコマンド

インストールすると、Claude Code の中で次のコマンドを使えます。

```text
/kokoro-mods status
/kokoro-mods export /absolute/path/export.json
/kokoro-mods export --print
/kokoro-mods allow-publish 30
/kokoro-mods focus 50
/kokoro-mods reset
```

`allow-publish` は1〜720分の許可を設定します。分数を省くと30分です。`focus N` は休憩通知の間隔をN分にして、タイマーを計り直します。`reset` は回数を消し、集計開始時刻を更新します。

ファイルへの書き出し、許可、focus の変更、reset は、本人が入力欄に打った場合だけ受け付けます。`status` と `export --print` は、ほかの呼び出し元にも応答します。

`check --json` はチェック結果をJSONで出します。`propose --json` は提案一式を標準出力にJSONで出します。警告・差分・要約・インストール手順は標準エラー出力に出します。この JSON には説明書の引用行も入るため、非公開で扱ってください。

`--max-enabled N` は最初に有効にする数を変えます。0も指定できます。`--all` は一致したすべてを有効にします。この2つは同時には使えません。`propose --lang ja|en` は表示言語を変えます。`recipes --lang ja|en` は、選んだ言語でカタログの名前、テンプレート、高い確信度で一致する節、パラメーターとその型を表示します。`--debug` は、入力本文を含めないエラースタック（エラーまでの呼び出しの記録）を追加します。

`fixtures/valid/en-generic.md` の提案要約の一部です。

```text
on   publish-guard  medium  quotes=1
on   lead-with-answer  medium  quotes=1
on   one-next-step  medium  quotes=1
off  focus-timer  medium  quotes=1
```

引用元は順に4・12・13・21行目です。非公開用レポートには、その言葉をコード用の囲みの中にそのまま載せます。公開の許可は既定で30分、回答の上限は12行です。休憩通知は50分に設定され、初めはオフです。`medium` は、この自由な形式の説明書で節が一致したことを表します。役に立つという証明ではありません。完全なレポートには、ほかの一致したレシピも載ります。

## レシピ

レシピは、Claude Code のふるまいを整える小さな部品です。17本の働きと、数えるものを並べました。

| レシピ | 何をするか | 何を数えるか |
|---|---|---|
| `lead-with-answer` | 結論から答え、説明を短くするよう求めます。 | `long_answers`：行数の上限を超えた回答 |
| `accept-typos-as-intent` | 誤字や表記の違いを指摘せず、伝えたいことを読み取ります。 | なし |
| `response-language` | 選んだ言語で答えるよう求めます。 | なし |
| `one-next-step` | 大きな仕事を分け、最後に次の行動を1つ示します。 | なし |
| `receive-only-fragments` | 設定した短い発言を、助言を添えずに受け取ります。 | `detected` |
| `respect-stop-signals` | 終了の合図を受け取り、次の仕事を追加しません。 | `detected` |
| `no-psych-framing` | 本人を解釈せず、書かれた希望に従います。 | なし |
| `publish-guard` | 許可した時間の外では、一致するBashの公開コマンドを止めます。 | `denied`、`allowed` |
| `quiet-confirmations` | 必要な許可を残し、日常の確認を繰り返しません。 | なし |
| `offer-options` | 複数案を比べてから1つを勧めます。 | なし |
| `plain-language` | やさしい言葉を使い、必要な用語には説明を添えます。 | なし |
| `expert-role-with-evidence` | 専門的な主張に根拠と確かめ方を求めます。 | なし |
| `trace-offers` | 決定や進み具合をどこに記録するか提案します。 | なし |
| `running-indicator` | 経過時間とツールの動きを示し、応答の処理が長くなると知らせます。 | `long_turns`、`suppressed` |
| `block-ahead-warning` | 認証や承認の手順を、その場面に来る前に説明します。 | なし |
| `session-resume-brief` | 前回からの日数と、そのときのターン数を示します。 | `resumed` |
| `focus-timer` | 前回の通知判定から動きがあった場合だけ、休憩を知らせます。 | `ticks`、`suppressed` |

`detected` は対象の発言が見つかった回数です。`suppressed` は、共通の通知間隔を守るためにお知らせを見送った回数です。「なし」のレシピには、動作回数の記録がありません。

## プライバシーと限界

CLI が読むのは、指定された説明書、提案JSON、集計JSON、任意で指定する設定ファイルだけです。`--out` の下に `plugin/.claude-plugin/{plugin,marketplace}.json`、`plugin/hooks/{hooks.json,register.ts,register.test.ts}`、`PROPOSALS.md`、`PROPOSALS.json` を書きます。その親には、準備用の一時フォルダーを作ります。入力や設定ファイルは編集せず、ホームの設定に自動で書き込むこともありません。

2つの提案レポートは非公開で保管してください。引用と、説明書のファイル名（フォルダーの部分を除いた名前）が入っています。共有するのは、確認済みの `plugin/` だけです。このフォルダーと各集計には、プラグイン名と説明書の SHA-256 が入ります。この指紋のような値で、同じ説明書を持つ人は、どの版から作られたかを確かめられます。説明書の中身は分かりません。

内容チェックのメッセージに出るのは、規則名と一致した語（`forbidden term "…"`）です。元の行そのものは出しません。

プラグインが手元に保存する活動記録は2種類です。開始時刻付きの動作回数と、作業ディレクトリごとの再開用の時刻・ターン数です。後者は、そのディレクトリのパスを鍵にして記録します。公開ガードは、許可の状態を管理するために有効期限も保存します。プロンプト、回答、ツール出力、説明書本文は保存しません。

本人が export を実行すると、指定した絶対パスへ書き出すか、`--print` でJSONを表示します。入るのは、プラグイン名、説明書のハッシュ、書き出し時刻、回数、真偽値（オン・オフ）や数値の設定だけです。フレーズ、パターン、言語など、文字列の設定値は含めません。

kokoro-mods は、説明書もこれらの記録もネットワークサービスへ送りません。カタログのルールは、Claude Code のモデルが読む情報に入ることがあります。説明書からの引用はプラグインに入りません。Claude Code 自体のデータ設定は変わりません。

公開ガードが保護するのは **Bashだけ**です。許可した時間の外では、一致する Bash の公開コマンドを止めます。ほかのツールや、内部で公開処理を行うスクリプトは対象外です。パターンの設定が空か、正規表現として読めない場合、`/config` で設定が直るまですべてのBashコマンドを止めます。ガードを切るには、レシピのオン・オフを切り替えます。

回数で分かるのは、どの動作があったかです。本人の負担が減ったか、この変更が改善の原因だったかは分かりません。プラグインAPIは早期アクセス版です。見本プラグイン（英語サンプルから生成器が出力したもの）と生成したプラグインは、Claude Code 2.1.290 と 2.1.291 で確認しています。それ以降の版でも動くかは、検証が必要です。

## KOKORO との関係

**KOKORO specification（KOKORO仕様）** は、本人のためのAI向け取扱説明書 `kokoro.md` の仕様です。心理師が臨床的な見立て（専門家としての状況の整理）を、AI にどう対応してほしいかという作業上の希望へ置き換えます。元の所見そのものは渡しません。仕様のリポジトリは執筆時点では非公開です。プロジェクトの公開部分は [kokoro-mcp](https://github.com/akihidem/kokoro-mcp) です。これは `kokoro.md` の署名・検証・失効・モデルへの配信を行う、ローダー兼 MCP サーバです。仕様と kokoro-mcp の作者は、Your Own Mod を設計した公認心理師です。

Your Own Mod は別のツールです。仕様の一部ではありません。

- 読むのは `kokoro.md`（frontmatter の `format: kokoro/...`、仕様の呼び方では `format_version`）、本人が書く `torisetsu.md`（`format: torisetsu/...`）、見出しのゆるい自由形式のプロファイルです。作業上の希望を見つけるためだけに読みます。診断名、心理師のレビュー、同意の項目は読まず、必須にもしていません。署名の確認もしません。
- 内容チェックは、仕様の禁止内容の規則に沿っています。診断名、検査の点数、自分を傷つける内容、安全規則を無効にする指示、ロールプレイの指示、文書の構造の崩れを拒否します（[設計書](docs/design/DESIGN.md) の付録A）。チェックを通るだけで、仕様に適合した `kokoro.md` になるわけではありません。仕様への適合確認・レビュー・署名は、仕様と kokoro-mcp の役割です。
- 説明書をモデルの文脈へ届けることはしません。それは kokoro-mcp の役割です。両者は並べて使えます。kokoro-mcp が説明書をモデルに渡し、Your Own Mod はいくつかの希望をフックに変えます。フックは、実行環境が強制して回数を数える処理です。
- このリポジトリには、仕様の本文も本物の説明書も含まれていません。サンプルの人物は架空です。生成した提案は、利用者の機械の中に留まります。

## 開発

Nodeの標準テストと、実際のプラグイン検証ツールを使います。

```sh
node --test test/*.test.mjs
claude plugin validate --strict docs/design/golden/plugin
```

`npm test` も、ファイル名のパターンであるglobを明示して使います。引数なしの `node --test` は、見本プラグインのTypeScriptテストまで拾うことがあるため避けてください。統合テストは、3つの正常なサンプルそれぞれからプラグインを生成します。空の一時 `HOME` で `claude plugin validate --strict` と `claude plugin test` を実行し、走った生成テストの本数と名前を確かめます。さらに、生成したモジュールを Node の型除去（型の注釈を取り除くしくみ）で実行し、そのモジュール自身が書き出す集計を検証します。

Claude がなければ、テストは `claude not on PATH; set KOKORO_MODS_SKIP_CLAUDE=1 to skip` と表示して失敗します。この環境変数を `1` にしたときだけ、対象テストを名前付きでスキップします。その場合、A2は未検証です。CIはNode 22・24で動き、Claude Code 2.1.290 をインストールします。インストールが失敗した場合だけ、スキップ変数を設定します。`main` とタグでは、インストールの失敗はジョブの失敗になります。

[設計](docs/design/DESIGN.md)、[公開インターフェース](docs/design/contracts/w4-interfaces.md)、[サンプルの固定データ](docs/design/contracts/w4-facts.md) に、契約と合格条件をまとめています。

終了コードは、0が成功とヘルプ、1が失敗（読めない・不正な入力ファイル、拒否した所有記録、予期しない失敗）、2が使い方の誤り、3が内容チェック不合格、4が差分あり、5が出力先の競合です。エラーはコードとキーを示します。入力本文の抜粋は出しません。
