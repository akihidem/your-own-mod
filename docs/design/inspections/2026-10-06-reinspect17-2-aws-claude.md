## 残っている指摘

**H-1（high・退行）** `src/catalog/index.mjs`、`JA_PUBLISH_ASK` の「自分で」lookbehind と、「レビュー後」の trigger
- **問題**：窓が、ただの て では止まらなくなりました。さらに、窓の中で止まる「もら・いただ」は、実際にはレビューの**後ろ**に来る語です。そのため「自分でテストしてレビューしてもらってからpushして」「自分で直してレビューしてもらってからpushして」では、レビューが本人の行為として除外されます。publish-guard の trigger がどれも成立せず、ゲートが消えます。どちらも普通の文です。
- **修正**：レビューの後ろに して(もら|いただ|くれ) か を(もら|受け|依頼) が続く場合は、自分で lookbehind をかけない別の選択肢として切り出す。lookbehind は「してから・の後」だけにかける。
- **テスト**：上の2文を正例として追加する。

**H-2（high）** `RECIPES` → publish-guard、ask…後 の linker と `JA_PUBLISH_WAIVER`
- **問題**：「確認は一旦後にしてpushして」「確認はとりあえず後にしてpushして」では、「後」の直前が は ではありません。しかも lookahead の `にして` は当たらないので、linker が成立してゲートがかかります。一方 waiver は「ask語(は|を|が)?」の直後に「後」が来ることを求めるので、これも外れます。確認を後回しにしたいという普通の依頼に、レシピの逆の結果が返ります。
- **修正**：
  - linker の除外を、に/で を食べる前に置く：`(?:後|あと)(?!にして|で\s*(?:も\|いい\|…))(?:に|で)`
  - waiver の ask語と「後」の間に、短い副詞の窓を許す：`[^。、]{0,6}`
  - 副詞を挟んだ否定例を追加する。

**M-1（medium・退行の可能性）** `JA_PUBLISH_WAIVER` の `回し`
- **問題**：「pushの確認は後回しにしないで」は確認を続けてほしいという依頼ですが、catalog の waiver に当たります。
- **修正**：`回し(?!に(?:しない|せず|するな))` とし、否定例を追加する。
- matcher 側の否定検査がこれを救うかどうかは、添付からは判断できません。

**M-2（medium・退行）** quiet-confirmations の trigger、`減らす(?!と(?!…いい|良い))`
- **問題**：「確認の質問を減らすといいとは思わない」が発火するようになりました。とは思わない の lookahead は動詞の直後でしか見ないので、「といい」を挟むと届きません。
- **修正**：いい・良い を外す。または 減らすと(…)の後ろに `[^。、]{0,4}とは[^。、]{0,6}(?:思|考)…(?:ない|ません)` が続く場合を除外する。

**L-1（low）** DESIGN.md §7 の publish-guard 行と quiet-confirmations 行
- **問題**：設計文がコードに追いついていません。publish-guard 行は「自分で」の窓（てから・でから・ず・もら・いただ）、quiet-confirmations 行は いい・良い・うれし が未記載です。
- **修正**：設計文を更新する。

**L-2（low）** `test/match.test.mjs`
- **問題**：Medium-1 の否定例が JA_STATE を通っていません。
- **修正**：否定例を「公開は私のブランチにCIがデプロイしてから」の形にする。
