## 残っている指摘

### H-1（high）`match.mjs` の `publishPolarity` と `hitFor`

**問題**

Medium-3 の処理は「確認を頼む言葉のない禁止は、ゲートを求める文ではない」という前提に立っています。ところが、このテストの差分自身がゲートを求める例として挙げている文の多くは、`PUBLISH_ASK` に一致しません。

- `confirm\b` は "confirmed" に一致しません。
- "until you hear from me"、"unless I'm OK with it"、「OKが出てから」に当たる語がありません。

そのため、次のようなごく普通の2文の箇条書きで、push のゲートが消えます。

- `Never push unless confirmed. Feel free to file issues without asking.`
- `Don't push until you hear from me. You can open new issues without asking.`
- 「pushは私のOKが出てから。イシューは確認なしで立てていい。」

どれも、2文目の issue のオプトアウトで `waiver=true` になり、`asking=false` のままセル全体がオプトアウトされます。前の2つの英文は、1文目がトリガーのテスト例そのままなので、トリガーが一致することは確かです。3つ目はトリガーが一致する場合に限ります。

**修正案**

オプトアウトの範囲を、トリガーの一致位置を含む文に限ります。`hitFor` で `match.index` を `publishPolarity` に渡し、オプトアウトの文がトリガーの一致を含まない場合は `waiver` を立てないようにします。

最低限の修正としては、次の2点です。

- `PUBLISH_ASK` を `confirm(?:s|ed|ing)?` にし、トリガーの条件語（unless / until / hear from / my OK / OKが出 / 教えて）を加える。
- Medium-3 のテストを `matchRecipes(...).length === 1` で、上の3つの文に対して確認する形に改める。

### M-1（medium）`QUESTION` の "whether" と「かどうか」の範囲

**問題**

"whether" と「かどうか」は節のどこにあっても疑問とみなされます。そのため `Feel free to push without asking whether I've reviewed it.` がオプトアウトにならず、本人がいらないと言った安全 mod が提案されます。安全側の誤りで、文の形もやや珍しいので medium にしました。

**修正案**

"whether" はオプトアウトの語句より前にある場合だけ数えます。「かどうか」は述語の位置（「かどうか迷う」「かどうか分からない」など）にある場合だけ数えます。

### L-1（low）`PUBLISH_OBJECT` に「切る」がない

**問題**

「イシューを切る」「イシューは確認なしで切っていい」は issue を作る意味の普通の言い方ですが、目的語として認識されません。オプトアウトが拾われないだけなので、安全側です。

**修正案**

主題形と `を(...)` の両方の枝に `切(?:っ|る|り)` を加えます。

### L-2（low）回帰テストの不足

**問題**

`QUESTION` の「か」の追加が、正しいオプトアウトを壊していないことを確かめるテストがありません。

**修正案**

「確認なしでpushしていいよ」「確認なしでpushしてOKだよね」が引き続き `waiver` になることを確認するテストを加えます。
