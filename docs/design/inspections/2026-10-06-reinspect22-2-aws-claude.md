## 残る指摘

**高1** — `src/catalog/index.mjs`、`JA_PUBLISH_WAIVER`（ので/から が付く、助詞のない形）
- **問題:** 「publishing 主題の述語なら waiver にしない」という判定が、目的語・助詞・ask 語が隣り合う時だけ働きます。普通の文 `リリースは私の確認後でいいので、先にリリースノートを書いて` を例にします。
  - 「私の」が間に入るので、lookbehind が効きません。
  - 後ろ側の目的語 `リリース` が、「リリースノート」の先頭部分に一致します。
  - その結果、waiver として blanking されます。残りの文 `リリースは私の` と `ノートを書いて` には ask 語が無いので、gate trigger 6 が当たっていても waiver が勝つ見込みです。
- 同じ型の文: `pushは私の確認後でいいので、先にPRを作って`、`pushは、確認後でいいので先にPRを作って`（は のあとの 、 が lookbehind の対象外）。
- 前提: publishPolarity の blanking の範囲は添付に無いので、上の説明（waiver 節を消した残りで trigger を読み直す）に従って推論しました。
- **修正案:**
  1. lookbehind を「同じ節の中で、先に publishing 目的語の主題がある」に広げる。例: `(?<!OBJECT\s*[はをの、][^。！？;；]{0,16}ASK)`。
  2. 後ろ側の目的語に語の終わりの条件を付け、`リリースノート` などを除く。
  3. テスト2件を asking 側に固定する。

**中1** — `src/catalog/index.mjs`、publish-guard の新しい trigger `OBJECT(は|を)?(その|それの)後(で|に)`（退行）
- **問題:** 前の節に ask 語・レビュー・人物が無くても当たります。例: `lintを直して、pushはその後で自由にして` は「確認なしで push してよい」という依頼ですが、「自由に」は waiver の語彙に無いので gate になります。逆向きの依頼に recipe が付きますが、気づきにくい語の並び方なので中としました。
- **修正案:** 同じ文の前方に `ASK|レビュー|査読|PERSON` があることを条件にする lookbehind を付け、反例を negative 側に固定する。

**低1** — `JA_PUBLISH_WAIVER` の新しい lookbehind
- **問題:** waiver の先頭語にある `OK` と `オーケー` が、lookbehind の ask 語の一覧にありません。そのため `pushはOK後でいいので先にPRを…` は waiver になります。
- **修正案:** 2つの一覧を1つの定数にまとめる。

**低2** — `JA_PUBLISH_WAIVER`、`に回(?=[しすさ])`
- **問題:** `後に回せばいいので先にpushして` が waiver でも gate でもなくなります（安全側）。
- **修正案:** `せ` を加えるか、設計に「受け入れる」と明記する。

**低3** — `test/match.test.mjs`
- **問題:** `全て` が設計の語の一覧に無いのに、テストにあります。
- **修正案:** 設計の一覧に `全て` を足すか、テストから外す。
