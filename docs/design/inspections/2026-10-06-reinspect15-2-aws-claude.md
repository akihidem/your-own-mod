## 見つかった問題

**H-1（high・今回の退行）** `src/catalog/index.mjs` RECIPES › publish-guard › `right('ja')` の2本目（ask 語 → 前|から → 公開対象）

- 問題：つなぎ語を「前・から」に戻した一方で、専用 trigger は `レビュー|査読` しか見ていません。そのため「確認後にpushして」「承認後にリリースして」「許可をもらった後でpushしてください」は、表示されているどの trigger にも当たらなくなりました。どれも安全ゲートを求めるふつうの文ですが、ゲートが消えます。
- 直し方：「後に・後で・あとで」をつなぎ語に戻し、直後に `(?!(?:いい|よい|良い|OK|構わない|かまわない|大丈夫))` を付けます。こうすれば「確認は後でいい」だけが除かれます。あわせて、上の3文を正例とする回帰テストを足してください。

**H-2（high）** 同じ箇所の、レビュー専用 trigger と `JA_PUBLISH_ASK` の両方にある `(?<!(?:自分で|セルフ)[^。、]{0,8})`

- 問題：間の8文字に動詞や「〜てから」の区切りが入っても、まとめて「自分のレビュー」と扱ってしまいます。例：「pushする前に自分でテストしてからレビューしてもらって」は、間が「テストしてから」の7文字なので、レビューが除かれます。ほかに ask 語がないので、ゲートが消えます。
- 直し方：間に入れてよい文字を、区切りを含まないものに限ります。例 `(?:(?!て|ず|から)[^。、]){0,8}`。この文を正例テストに足してください。

**M-1（medium）** quiet-confirmations の trigger に足した `減らす`

- 問題：辞書形には要望でない使い方があります。「確認の質問を減らすとミスが増える」（減らしたくない、という意味）、「減らすかどうかは私が決める」でも recipe が作動します。
- 直し方：`減らす(?!と|かどうか|か)` にします。または、「減らすように・減らしてほしい・減らすのがいい」などの依頼の形だけを受け付けます。

**L-1（low）** `JA_BARE_NEG_TAIL` の上のコメント

- 問題：コメントは「つらい は結果ではない」と書いていますが、コードでは つらい が結果の語に入りました。
- 直し方：コメントを「厳しく だけを除く」に直します。

**L-2（low）** 設計文書の publish-guard の行

- 問題：レビュー一覧に「後」が残っています。
- 直し方：その「後」を消し、「専用の形」と書いた注記に寄せます。

**L-3（low）** `JA_SAYSO` の `(?<!CIの)チェック`

- 問題：「lintのチェック」「Actionsのチェック」「CI のチェック」（空白入り）は、まだ本人の了承として読まれます。ゲートが残る側に倒れる誤りなので安全側です。
- 直し方：`(?<!(?:CI|lint|テスト|ビルド)\s*の)` にします。
