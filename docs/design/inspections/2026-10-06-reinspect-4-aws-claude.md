# kokoro-mods chunk C 再検品（emitter・テンプレート差分）

添付だけで判断しました。添付に無いもの（`constants.mjs`、カタログ、`renderManifest`、Node runner の A6）は推測で補わず、最後に「判断できなかった点」として挙げています。

## 1. 「folded」とした各行は、実際のコードで実装されているか

| 行 | 判定 |
|---|---|
| needles を全 quote・全 matched に広げる | **実装されています。** 長さ2以上で正規化（NFKC・小文字化）。短い quote と matched は、カタログ・テンプレート原文・プラグイン名のどれかに含まれる時だけ除外されます。`LEAK_CHECK_MIN_CHARS` 以上の quote は、常に検査対象になります。 |
| `pluginName` の検証（`E_PLUGIN_NAME`） | **実装されています。** ただし `PLUGIN_NAME_PATTERN` が文字列の先頭から末尾まで固定されているかは、添付から確認できません。 |
| bundle の他の欄（`E_BUNDLE`） | **一部だけです。** sha256・version・confidence・enabledByDefault は値まで調べています。`params` は「null でない object か」だけで、キーも型も範囲も調べていません（指摘 M1）。 |
| NFKC と大文字小文字の違い | **実装されています。** `leakCheck` は検索対象も needle も同じ `fold` を通し、JSON エスケープ後の綴りも探します。 |
| パターンを全部コンパイルしてから照合する | **モジュール側は実装されています。** 配列か、全部文字列か、`'u'` 付きで全部コンパイルできるか、の順に調べ、だめなら `bump('denied')` してから拒否します。**golden 側は同じ形になっていません**（指摘 L1）。 |
| `BOOLEAN_DEFAULTS` | **実装されています。** manifest の boolean 欄から作られ、`normalizeOptions` で既定値に戻します。 |
| `NUMBER_BOUNDS` | **実装されていますが、範囲付きです。** min と max の**両方**が数値の param だけが範囲内に収められます。片方しか無い param には効きません（指摘 L2）。 |
| `resetState()` | **書かれてはいます**（`register` の先頭で呼ばれます）。ただ、モジュール全体の状態をすべて戻しているかは、`register.mjs` の全文が無いので確かめられません。 |
| composer ゲートのテスト | **実装されています。** `reset` を実行し、拒否の文面と完全に一致するかを見ます。無関係なハンドラーが答えた時は `'unexpected bottom'` が返るので区別できます。 |
| 否定ケースを各検出器の下に置く | **一部だけです**（指摘 M2）。 |
| compose テストの行数とプレースホルダー | **実装されています。** ただしプレースホルダーの検査は、名前を決め打ちした一覧です（指摘 L3）。 |

## 2. 改修で生じた退行（regression）

- **R1（medium）** パターンのコンパイルに `'u'` フラグが付くようになりました。以前は通っていたパターン（例：`\-` や `\'` のような単独のエスケープ）が、u モードでは構文エラーになります。しかも 1 本でもコンパイルに失敗すると、公開コマンドに限らず**すべての Bash 呼び出し**が拒否されます。
- **R2（low）** 停止検出だけの bundle から、`疲れたけどやる` と `疲れたのでレビュー` の否定ケースが消えました。どちらも停止の語句 `疲れた` で始まり、停止検出の後置きガードを確かめていたケースです。

## 3. 手記（manual）の文が外へ出る新しい経路

- `E_LEAK` のエラー文は `path` だけを含み、needle は含みません。`assertEmittable` の文面は固定文と添字だけです。**新しい出口は見つかりませんでした。**
- metrics export の `options` は `OPTION_KEYS`（number と boolean の欄だけ）に絞られているので、文字列の param は出ません。
- 新しい経路ではありませんが、**構造的な防御が「evidence を除く」という引き算だけ**になっている点が残っています（指摘 M1）。

## 4. 否定ケースは「ガードの証明」になっているか

- **停止検出の否定ケース**
  - `一旦やめるかどうか` と `stop for now!×29` は、同じ語句の肯定ケース（`一旦やめるね`、`!×28`）と対になっているので、**ガードの証明になっています**。
  - `あとで…` 系 5 本、`終わり…` 系 3 本、`wrap up this function…` は、`あとで`・`終わり`・`wrap up` そのものが発火する肯定ケースがありません。これでは「ガードが効いた」のか「語句が最初から発火しない」のかを区別できず、**ガードの証明になっていません。**
- **受け取り（receive）検出の否定ケース**：`眠い`・`tired`・`疲れた` の肯定ケースも、この検出器の語句設定も添付に無く、判断できません。
- **共通ブロック**：`はい` は、どの語句でも始まらない文なので、ガードの証明ではありません（コメントもそう説明しており、正直な書き方です）。途中に `眠い.` を含む長文は、`眠い` 単独の肯定ケースがある場合に限り、「語句が文頭でだけ発火する」ことの証明になります。
- **reset の拒否**：拒否の文面との一致はゲートが働いた直接の証拠です。一方で、コメントの「次の export のカウントが、何もリセットされていないことを示す」は、事前に何もカウントしていなければ中身の無い主張です。

## 5. 残る指摘

**M1（medium）** `src/emit.mjs` の `assertEmittable` / `stripEvidence`
- **問題**：`params` は形しか調べていません。さらに `stripEvidence` は `...bundle` と `...proposal` で、evidence 以外の欄を全部テンプレートへ渡します。CLI が手記から作った文字列 param（語句・パターンなど）や未知の欄があると、`plugin/**` に入ります。`leakCheck` が捕まえられるのは、「needle 全体を含む」場合だけです。quote の**一部分**を写した param は捕まりません。
- **修正案**：`params` のキーが `recipes[id].params` にあるか、型が合うか、数値が min/max 内か、文字列や配列がカタログの既定値か列挙値か、を emit 時に照合します。stripped な bundle は、既知の欄だけを並べて作り直します（足し算にする）。

**M2（medium）** `src/templates/tests.mjs` の停止ブロック
- **問題**：上記 4 のとおり、`あとで`・`終わり`・`wrap up` の否定ケースが、ガードの証明になっていません。
- **修正案**：`'あとで'`、`'あとで。'`、`'終わり'`、`'終わりー'`、`'wrap up'`、`'Wrap up.'` を note 付きの肯定ケースとして加えます。停止ブロックには `'疲れたけどやる'` も戻します。

**M3（medium）** `src/templates/register.mjs` の publish guard ハンドラー
- **問題**：上記 R1 です。設定が不正だと全 Bash が拒否されるのに、文面は「publishing denied」で、何が止まったのか分かりません。公開と関係ないコマンドでも `denied` カウンターが増えます。カタログの既定パターンが `'u'` でコンパイルできる保証もありません。
- **修正案**：emit 時に、各 proposal とカタログ既定のパターンを `new RegExp(src,'u')` で検証して落とします。拒否文は「Bash 全体を止めている」ことと直し方が分かる形にします。設定不正による拒否は、別のイベント名で数えます。

**L1（low）** golden の `register.ts`
- **問題**：配列か・全部文字列かの確認と `bump` がありません。そのため `[5]` が `/5/` として受理され、文字列 `"rm"` は 1 文字ずつのパターンに分解されます。テンプレートとも DESIGN §7 とも食い違っています。
- **修正案**：生成器の出力から golden を作り直し、テストで出力とバイト単位で照合します。

**L2（low）** `register.mjs` の `renderRegister`（numberBounds）
- **問題**：min だけの param は範囲に収められないので、コメントにある「間隔 0 のタイマーは起きない」が保証されません。既定値そのものが範囲外かどうかも、emit 時に調べていません。
- **修正案**：min と max を片側ずつ適用し、emit 時に `default ∈ [min,max]` を確認します。

**L3（low）** `tests.mjs` の compose テスト
- **問題**：プレースホルダー名が決め打ちなので、カタログに新しい名前が増えると検出できません。
- **修正案**：`/\{[a-z_]+\}/` で一般的に検査します。

**L4（low）** `emit.mjs` の `leakNeedles` / `emitPlugin`
- **問題**：`LEAK_CHECK_MIN_CHARS` 以上の quote が正当にカタログ文と一致すると、`E_LEAK` が誤って出て、その recipe を引き起こした bundle 自体を出力できなくなります（例：手記の行がちょうど `stop for now` の場合）。カタログに含まれる文は選択の事実以上を明かさないので、除外しても安全です。また、エラーにどの証拠かが出ないので、利用者は直しようがありません。
- **修正案**：長い quote もカタログ本文（STATIC_SOURCES は除く）と一致すれば除外します。エラーには proposal の添字と evidence の添字だけを出します（本文は出しません）。

**L5（low）** `emit.mjs` の `assertEmittable`
- **問題**：evidence の要素に `null` があると、`leakNeedles` の分割代入で TypeError になり、`E_BUNDLE` コードが付きません。version の正規表現は `1.0.0-rc.1+build` を拒否します。
- **修正案**：evidence の各要素が object かを調べ、正規表現をプレリリース部とビルド部に分けます。

**L6（low）** `register.mjs` の `resetState`
- **問題**：前回の登録で実行途中だった非同期ハンドラーが、リセット後に再開すると、新しい登録の状態（`timer` / `focusTimer`）に書き込めます。再登録のテストもありません。
- **修正案**：登録ごとの世代番号を持ち、非同期処理の再開時に照合します。生成テストに「2 回登録しても状態が持ち越されない」ケースを加えます。

## 判断できなかった点

- `PLUGIN_NAME_PATTERN` が先頭・末尾まで固定されているか。`LEAK_CHECK_MIN_CHARS` の値。
- CLI が `params` や proposal の他の欄を手記から作るか。`renderManifest` が bundle や proposal を丸ごと出力するか。
- カタログ側の `recipe.evidence` の中身（除外対象の材料に入っているため）。
- モジュールの状態変数の全一覧（`resetState` で全部戻しているか）。
- 受け取り検出の語句と肯定ケース。カタログ既定パターンが `'u'` でコンパイルできるか。
- A6（Node runner）の実際のテスト。`PHRASE_SUFFIX` と DESIGN §6。`$.session.cwd` の型宣言。
- 生成テストが実際に緑かどうか（実行結果が添付されていません）。
