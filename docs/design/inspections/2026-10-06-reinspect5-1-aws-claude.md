## 処置で入った退行

**High-1：普通の待機解除文が伝聞として読まれる**
- **場所：** `REPORTED_IN`（`publishPolarity` の中）
- **問題：** `(?:って|と)(?:言|いう|…)` を節の中のどこでも探しています。そのため「pushは確認なしでいいという方針にします。」が伝聞扱いになり、ゲートを外したい文に publish-guard が提案されます。
- **経路：** `reported=true` → `permitted=false` → 否定された待機解除として扱われ、`asking=true` になります。処置の前は、この判定は `REPORTED` が後続の節だけを見ていたので、`いい`+`と` が許可として通っていました。
- **巻き添え：** 「ちょっと言いにくいけど…」の「と言」にも一致します。
- **修正案：** 伝聞は話し手を伴う形に限ります。たとえば `(?:って|と)(?:言(?:う|って(?:い)?る)(?:人|方)|言われ(?:た|て))` とし、`という(?:方針|ルール|こと(?:に|で))` は除外します。

**Medium-1：no longer を文全体で禁止として扱う**
- **場所：** `PROHIBITION`（`publishPolarity` の中）
- **問題：** "Pushing no longer needs my OK — go ahead and push without asking." では、節の中で "go ahead" が許可になります。しかし文全体に no longer があるため、ゲートが残ります。no longer が確認の側にかかる二節の文だけで起きます。
- **修正案：** `no\s+longer` は許可語に係る形だけにします。たとえば `(?:can|may|is|are)\s+no\s+longer\s+(?:ok|allowed|fine|push)` に絞り、`(?:need|require)s?\s+no\s+longer` の形は禁止に数えません。

**Medium-2：命令に付ける "…, OK?" が疑問として読まれる**
- **場所：** `publishPolarity` の question 判定
- **問題：** "Just push without asking, OK?" では、`IMPERATIVE_WAIVER` が成立しているのに、文末の `?` で question になり、ゲートが残ります。付加疑問を使う修辞の形なので Medium としました。
- **修正案：** 文末の疑問判定では、`?` の直前の語が `(?:ok|okay|alright)` で、前の節が命令の待機解除のときは疑問にしません。

## 処置以前から残っている指摘

**Medium-3：許可の先読みが「でしょう」で止まる**
- **場所：** `PERMISSION`（いい/よい の先読み）
- **問題：** 「pushは確認なしでいいでしょう」は、先読みに `でしょ` が無いので許可になりません。ゲートを外す方向の文がゲート要求として扱われます。「いいけど」も同様です。
- **修正案：** 先読みに `でしょ`・`けど`・`けれど` を足します。

**Low-1：形容詞の語幹一覧に漏れがある**
- **場所：** `PERMISSION`（語幹の否定後読み）
- **問題：** 「かっこいい」「気持ちいい」が節末にあると許可語として数えられます。
- **修正案：** 語幹に `かっこ`・`ちが`・`ちの` を足します。

**Low-2：issue の扱いが設計文と食い違う**
- **場所：** `PUBLISH_OBJECT`
- **問題：** 一つは、"open a new issue" が冠詞と new の重なりで一致しないことです。ただし、対象語が見つからなくても待機解除を見落とすだけで、ゲートが外れることはありません。もう一つは、「issueの」は起票でなくても公開対象として数えるので、§5.4a の「起票したものだけ」と食い違うことです。
- **修正案：** `(?:an?\s+|the\s+)?(?:new\s+)?` に変えます。和文側は `issue(?:を)?(?:作成|起票|立て)` に絞ります。
