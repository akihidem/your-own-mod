## 4. 残っている指摘

**H-A（high）match.mjs `REPORTED` / `REPORTED_IN`（publishPolarity から使用）**
- 問題：`方(?!針|法)` は除外する語を列挙しています。そのため「pushは確認なしでOK、という方向でお願いします」が、話し手のいる伝聞として扱われます。結果として確認省略が否定されたことになり、確認をはさむ安全 mod が提案されてしまいます。前回の H-1 と同じ型で、文も普通の文です。「という方式」「という方が早い」も同じです。
- 直し方：話し手を肯定形で書きます。たとえば `(?:人|方)(?:が|も|は)?(?:いる|いた|多い)`。「という声／話／噂」も同様に存在の述語を要求します。回帰テストに「方向」「方式」の文を加えます。

**H-B（high）match.mjs `PROHIBITION`**
- 問題：否定語のあとにはさまれる語として認めているのは、副詞を2語までです。"Pushing without asking isn't something I'm OK with." では「OK」が許可語として拾われ、禁止として扱われないので、確認の仕組み（ゲート）が外れます。一人称の判定（`habit`）は `stated` 側しか止めず、`PERMISSION` の経路には効きません。
  - 似た文："is not something I'm fine with"（medium 相当）、「OKした覚えはない」（medium）。
- 直し方：isn't / aren't / wasn't / is not を、don't と同じく文中にあれば単独で禁止として扱います。あわせて `habit` を `PERMISSION` の経路にも効かせます。

**M-A（medium）match.mjs `QUESTION`**
- 問題：「確認なしでpushしても大丈夫ですかね」は質問として扱われず、「大丈夫」が許可になってゲートが外れます。ただ、手帳の文としては珍しい形です。
- 直し方：語尾のあとに `(?:ね|な|ねえ|なあ)?` を許します。「のか」「の」で終わる形も加えます。

**M-B（medium）match.mjs `PUBLISH_OBJECT`**
- 問題："You can open new issues without asking" と「イシューは確認なしで立てていい」で、発行の対象が見つかりません。確認省略が無視されるので、ゲートが誤って残る可能性があります。ただし trigger が当たるかどうかは不明です。
- 直し方：`(?:an?\s+|the\s+|new\s+)` を受け付けます。「イシュー」「issue」に「は／も」が付いた主題の形で、同じ節に動詞（立て／作／出／起票）があれば対象に含めます。

**L-A（low）match.mjs okTag**
- 問題：読点「、」による付加（「pushして、OK？」）は付加語として扱われず、質問になります。安全側に倒れるだけなので、影響は小さいです。
