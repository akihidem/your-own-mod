## 2. 残っている指摘

### HIGH

**H-1 `src/catalog/index.mjs` quiet-confirmations の箇条書き trigger（英語・日本語）**
- **問題**：今回足した形に、否定を見る仕組みがありません。
  - 英語：「確認を省く・やめる」系の語の並び（例：skip confirmations）が否定の有無を見ずに当たります。そのため "Never skip the confirmation before deleting"（削除前の確認は絶対省かないで）や "Don't stop checking in" で quiet-confirmations が発火します。これは確認を減らす提案で、本人の意図と逆です。
  - 日本語：`(?:やめ|…|減らし)` が「確認の質問はやめないで」「確認を減らしたりしないで」の中の文字列にも当たります。
- 「提案は落とすことがあっても、反転はさせない」という方針の最も重い違反方向です。
- 添付されていない `unless`（"Requiring repeated confirmation…"）がこの否定形を全部打ち消せているなら、中程度に下げられます。ただし添付からは確認できません。
- **修正案**：
  - 英語の行に、前の否定を見る lookbehind（`(?<!\b(?:never|not|don['’]t|do not)\s)`）を付ける。
  - 日本語の動詞の後に `(?!(?:ない|ないで|ません))` を付ける。
  - 両方の否定形をテストに入れる。

### MEDIUM

**M-1 publish-guard の英語 trigger（4本）**
- **問題**：
  - 1本目と5本目は `push(?!\s+notifications?)(?:ing|es)?` という形です。"Ask me before pushing notifications" や "pushing notifications without asking" がすり抜けます。
  - chunk D の新しい行（`never/don't push` と ask 系の語の組）には notifications の除外が一切ありません。そのうえ `[\s\S]*` を使っているので、文の区切りを越えて ask 系の語を拾います。
- 旧来の行単位の unless を外したので、これは新しい誤爆です。
- **修正案**：
  - lookahead を語尾の後ろへ移す（`push(?:ing|es)?(?!\s+notifications?)`）。
  - 新しい行にも同じ除外を足す。
  - `[\s\S]*` を `[^.!?;]*` に変える。
  - ハイフン付きの "push-notification" も除外に含める。

**M-2 lead-with-answer の日本語 unless `短く(?:答|まと|返|書)\S*?ない`**
- **問題**：日本語には空白がないので、`\S*?` は句点を越えて行末まで伸びます。「短くまとめて。冗長な説明はしないで」は「しないで」の中の「ない」に当たり、本来の趣旨（短く答えてほしい）の要望が打ち消されます。
- **修正案**：`短く(?:答え|まとめ|返さ|書か)(?:ない|ないで)` のように動詞の活用形に固定する。または間を `[^。！？、]{0,3}` に限る。

**M-3 lead-with-answer の日本語の対象名 unless（`…|PR)` に `iu` フラグ）**
- **問題**：`PR` に語の境界がないので、大文字小文字を問わず "prompt"・"project"・"print" の中の pr に当たります。たとえば「この project では返答は300字以内」は行ごと打ち消されます。
- また行全体を見る lookahead なので、「コミットは小さく。返答は200字以内」のように別の文にある返答の字数制限まで消えます。
- **修正案**：`(?<![A-Za-z])PRs?(?![A-Za-z])` にして大文字小文字を区別する。対象名と数字が同じ句の中にあることを要求する（例：`(?:件名|…)[^。、]{0,12}?\d+字`）。

### LOW

- **L-1** accept-typos の英語 unless：
  - `point (?:them|it) out` が誤字の話に限られていません。"Ignore my typos; if the build breaks, point it out" で誤字を受け入れる方針が消えます。
  - 否定の lookbehind に "do not ever" がありません。
  - 日本語の「教えてくれなくていい」は、`なくて` を直後でしか見ないので打ち消しが起きます（安全側ではあります）。
  - 修正案：対象を typo・spelling を含む句に限り、否定の形を足す。
- **L-2** expert-role の unless：
  - `\bI (?:work|am|'m|was)` は "I'm" と曲がった引用符の "I’m" に当たりません。
  - 修正案：`\bI(?:\s+(?:work|am|was)|['’]m)\b`
- **L-3** block-ahead-warning：
  - `失速(?:する|して)?` は語尾が任意なので、「売上が失速」のような無関係な文も trigger になります。
  - 修正案：語尾を必須にし、認証・承認・確認・ダイアログのどれかが同じ句にあることを要求する。
- **L-4** respect-stop-signals：
  - 「あとで出したら見て」は stop signal になってしまいます。
  - 「おわりって言ったら」は `って` が許されていないので取りこぼします（旧版は拾っていたので退行）。
  - 修正案：`(?:を|と|って|の)?` にし、「出したら」には合図・シグナルを必須にする。
- **L-5** `EN_CHAR_LIMIT` の上のコメント「unit-boundary branch also accepts…」が古いままです。その分岐は削除されているので、コメントを消すか書き直します。
- **L-6** JA_CHAR_LIMIT の `[^。、,;]` は読点を通さないので、「回答は、200字以内」から値が出ません。また「関数の説明コメントは50字以内」は「説明」が返答の語として扱われ、50 が derive されます（`コメント` は除外リストにありません）。
