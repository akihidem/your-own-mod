# Prior art and evidence survey (2026-10-06)

Purpose: before designing kokoro-mods, look at what already exists (GitHub, marketplaces, research) so the design builds on it instead of reinventing it. Searched with `gh search repos`, web search, and arXiv/ACM abstracts on 2026-10-06. Star counts and dates are as seen that day and age quickly.

Pattern across all of them: **the input is a label ("I have ADHD"), the output is one generic rule set**. None reads an individual profile, none uses function hooks (the newer plugin API that can enforce, draw, time and store), none measures whether the change helped, and none handles the privacy question (a profile that must not leave the machine).

## 3. Evidence on the need

- Vella & Blincoe, *The Impact of AI Coding Assistants on Software Engineering: A Longitudinal Study* (arXiv 2605.23135): matched cohort of 95 engineers over 6 months; 84% report productivity gains at both points, but the share reporting a worsened developer experience in at least one dimension rose from 14% to 27%; **flow state and cognitive load got worse while feedback loops improved**; work shifted to "supervisory engineering" (direct, evaluate, correct AI output). Confidence: high (peer-style preprint, numbers from abstract).
- METR 2025 RCT: experienced open-source developers were 19% slower with AI tools while believing they were about 20% faster. Confidence: high (widely replicated citation).
- *Differences between Neurodivergent and Neurotypical Software Engineers* (arXiv 2506.03840, analysing the 2022 Stack Overflow survey): 10.6% of respondents report concentration/memory challenges such as ADHD, 4.3% autism; samples n=1,305 (ADHD), 374 (ASD), 363 (dyslexia); engineers with ADHD report **more interruptions caused by waiting for answers** and less interaction outside the team. Confidence: high.
- *Two's a Crowd: Human and AI-Based Copresence for Developers with ADHD* (arXiv 2609.21254, 14 interviews): AI copresence keeps accountability and flow **without reputation management or surveillance anxiety**; recommendations mapped to SPACE. Confidence: medium (qualitative, n=14).
- ASSETS 2025 paper on programmers with ADHD (UMass): not retrievable at fetch time (404); listed for follow-up.
- cogsync (author's own frozen project, 2026-09-03): measured that the bottleneck was not the AI quota but **"how much the person re-reads at every session switch"** (30-90 session contexts per day). Any band/indicator design should reduce re-reading, not add to it.
- claude-env-coach v2 → v3 (author's own): 814 LLM-written proposals, 0 adopted; v3 fixed it by counting from the person's own records, capping open prescriptions at 3, detecting adoption from settings changes, and measuring 7 days after. kokoro-mods inherits these four rules.

## 4. What is missing, and therefore what kokoro-mods is

1. **Profile-driven, not label-driven.** Each proposal must cite the verbatim line of the person's own manual that triggered it. No diagnosis label is read or needed (KOKORO §7 forbids them anyway).
2. **Hooks with teeth.** Function-hook mods can refuse a tool call, rewrite a prompt, add a system-prompt section, draw a band, run a timer, and keep counters. Skills can only ask the model nicely.
3. **Proposal, not auto-apply.** Generated mods are written to a folder the person chooses; nothing touches `~/.claude` without `/plugin install`. At most a few proposals open at a time.
4. **Measured.** Every generated mod counts what it did (fired, shown, suppressed) as numbers only, so a later report can say whether anything changed.
5. **Nothing leaves the machine.** The generator is deterministic and offline by default; no profile text is sent to any model. (Matches KOKORO principle 1 and kokoro-edge's "data never leaves the device".)

## 5. Adoption gates for reusing code (license / maintenance / fit)

- `i-have-adhd` rules: reference only (text rules; our brevity recipe cites it as evidence, we do not copy its files).
- `claude-adhd` (shaheer-00) transcript indexer: reference only (no license stated → cannot adopt).
- `ravila4/claude-adhd-skills` nudges: reference (MIT, but command hooks; we implement timers as function hooks).
- `ai-torisetsu/check_torisetsu.py`: adopt the rule list (same author, MIT), ported to the generator's content check.
- Claude Code plugin API examples (band.tsx, tool-call.ts, pane.tsx from the plugin-authoring skill): reference for template shapes.
